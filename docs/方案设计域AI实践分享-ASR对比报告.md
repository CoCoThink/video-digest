# 《方案设计域 AI 实践分享》ASR 对比报告

> 测试日期：2026-07-20
> 输入：`test/方案设计域AI实践分享.mp4`，5714.155 秒（01:35:14）
> 硬件：NVIDIA GeForce RTX 3050 Laptop GPU 4 GB

## 1. 测试配置

两种模型均使用 16 kHz 单声道 PCM、30 秒分块和项目当前 `layout` 参数。

- Qwen：Qwen3-ASR-1.7B int8 GPU + Qwen3-ForcedAligner-0.6B FP32 CPU，使用服务端 GPU/CPU 重叠流水线。
- FireRed：FireRedASR2-AED BF16、beam 1；异常块检测和递归二分重试已开启；另对同一 items 按时间块运行 CPU FireRedPunc。
- 两者均输出 SRT、TXT、逐 token `items.json` 和指标 JSON。

## 2. 性能与资源

| 指标 | Qwen3-ASR-1.7B int8 | FireRedASR2-AED |
|---|---:|---:|
| 预处理 | 10.972 s | 6.400 s |
| 模型加载 | 18.057 s | 11.456 s |
| 转写/推理 | 3760.139 s | 655.279 s |
| 转写 RTF | 0.6580 | 0.1147 |
| 端到端 | 3790.096 s（63:10） | 680.158 s（11:20） |
| 峰值显存 | 2.649 GB | 2.567 GB |
| 异常/重试 | 0 | 0 |

FireRed 本次端到端约为 Qwen 的 **5.57 倍速**，峰值显存低约 82 MB。
Qwen 使用 30 秒分块后全程没有 OOM、Worker 崩溃或对齐异常。

FireRedPunc 额外推理 15.463 秒（RTF 0.00271），一次性加载 5.998 秒；常驻服务按
任务只计推理时，FireRed + Punc 约 695.621 秒，仍为 Qwen 的 **5.45 倍速**。

## 3. 覆盖与时间轴

| 指标 | Qwen | FireRed |
|---|---:|---:|

| 对齐字符 | 25,370 | 25,496 |
| token | 25,029 | 25,235 |
| cue | 1,572 | 825 |
| 最后 token | 5706.337 s | 5707.265 s |
| cue 显示覆盖率 | 84.3% | 93.7% |
| >5 秒 cue 空档 | 20 | 14 |
| 最大 cue 空档 | 25.5 s | 24.6 s |
| 非法/重叠 cue | 0 | 0 |

Qwen 的归一化正文与对齐 token **25,370/25,370 完全一致**，本次没有后处理
丢字。191 个 30 秒窗口中不存在“只有一个模型有正文”的整窗漏识别。两者的
最大空档也出现在同一段 `69:11–69:37` 左右，属于共同的低语音/停顿区。
该 25 秒区间实测平均音量 `-67.6 dB`、峰值 `-34.0 dB`；前一有声区间平均
`-19.7 dB`、峰值 `-5.1 dB`，因此不是双方共同漏识别。

FireRed cue 显示覆盖率更高不等于识别更多：两者对齐字符只差 0.5%。主要原因是
FireRed AED 无标点，347/825 条 cue 被布局层延长并裁到 7 秒上限；Qwen 有标点，
语义分句更短，只有 19/1572 条触及上限。

### 3.1 FireRedPunc 可读性复跑

| 指标 | FireRed AED 原始 | FireRed + Punc | Qwen |
|---|---:|---:|---:|
| 正文字符（含标点） | 25,710 | 27,568 | 28,014 |
| 新增标点 | - | 1,983 | ASR 原生 |
| cue | 825 | 1,372 | 1,572 |
| 7 秒裁剪 cue | 347 | 87 | 19 |
| > 9.5 CPS cue | 0 | 1 | - |
| 字符投影降级 | - | 0/191 块 | - |
| 非法/重叠 cue | 0 | 0 | 0 |

Punc 只增加展示标点，不改变原始字母、数字、大小写和 timed items，因此领域词准确
度结论不变。它明显收窄了 FireRed 的断句差距，但 Qwen 在这条视频上仍有更少的
7 秒裁剪 cue。

## 6. 结论

在这条方案设计领域视频上，Qwen 与 FireRed 的总体文本高度一致，且都完整覆盖
到结尾。**Qwen 在核心中文领域词和英文缩写方面更稳，成品字幕质量仍更适合作为
默认方案；FireRed + Punc 的主要优势是约 5.45 倍速度，并已具备可用的标点断句。**

FireRed 并非全面落后，它在“应用架构”“产物/skill”“详设”等片段上明确更好；
因此当前证据仍不支持任何一方“完全超过”另一方。产品上建议维持 Qwen 默认、
FireRedASR2-AED + CPU FireRedPunc 快速模式的双 backend 方向。若要确定纯准确率，需要为多个时间片制作人工
逐字稿并计算 CER/WER。

服务端的 backend 契约、异常分块重试、标点投影和上线门槛见
`docs/FireRedASR-v2-接入设计.md`。
