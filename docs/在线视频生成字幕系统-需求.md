## 1. 背景与现状

### 1.1 背景

用户手中常有本地视频（课程、讲座、会议录像等）需要配字幕。现有做法要么把整个视频上传到云端服务（上传量大、隐私顾虑），要么在本地手动跑命令行工具（门槛高）。本系统提供一个浏览器即可使用的字幕生成服务：**视频不出本机，只上传音频**，由后端 GPU 服务完成语音识别并生成可下载的字幕文件。

### 1.2 已验证的技术基础（现状）

本机已跑通完整离线管线（详见实测报告），核心结论：

- **模型方案已定型**：Qwen3-ASR-1.7B int8 量化 + Qwen3-ForcedAligner-0.6B（CPU），在 4 GB 显卡（RTX 3050 Laptop）上全 GPU 运行，峰值显存 3.02 GB；10 分钟音频总耗时约 6.4 分钟。备选快速方案 Qwen3-ASR-0.6B 约 2.5 分钟，准确度略降。
- **字幕后处理已完成**：标点断句（`build_srt_punct.py`）+ 排版规范化（`build_srt_layout.py`，含最短/最长时长、阅读速度、折行、jieba 中文分词防劈词），产出接近人工水准的 SRT，且纯 CPU、秒级完成。
- **中间产物机制**：ASR 阶段落盘 `items.json`（全文 + 逐 token 时间戳），后处理可离线重跑，无需重新占用 GPU。

本需求即在此离线管线之上，包一层「浏览器前端 + HTTP 服务」，使之成为可供用户自助使用的在线系统。

## 2. 系统目标与范围

### 2.1 目标

1. 用户通过浏览器选择本地视频文件，**无需上传完整视频**，浏览器端**无损提取**音轨（只解封装、不重编码）后仅上传音频。
2. 后端服务调用 Qwen3-ASR 模型完成转写与时间戳对齐，经标点断句与排版规范化后生成字幕文件。
3. 用户可在页面上查看进度、预览结果，并下载字幕文件。

### 2.2 范围内（In Scope）

- 浏览器端：视频文件选择、音频抽取与降采样、音频上传、进度展示、字幕预览与下载。
- 服务端：音频接收、任务排队、ASR 转写 + 强制对齐、标点断句、排版规范化、字幕文件生成与下发、临时文件生命周期管理。
- 输出格式：SRT（必须）、纯文本 TXT（必须）、WebVTT（可选）。
- 语言：支持**纯中文、纯英文、中英混合**视频，沿用模型自动语言识别能力（`language=None`）。

### 2.3 范围外（Out of Scope，本期不做）

- 快速模式（0.6B 模型）：4 GB 显存无法双模型常驻，按需切换加载会引入显著复杂度（卸载/加载逻辑、队列聚簇），本期仅提供标准模式（int8-1.7B），快速模式列为 P2。
- 字幕在线编辑、人工校对协作。
- 翻译字幕 / 双语字幕。
- 用户账号体系与多用户隔离。本期单用户/内网定位，历史任务列表（FR-F8）对所有访问者可见、不做归属隔离；公网多租户场景的账号与鉴权列为后续。（注：任务结果本身长期保留、仅用户主动删除，见 FR-B7；此处范围外的是"多用户隔离"，非"结果保留"。）
- 视频烧录字幕（硬字幕）。
- LLM 纠错、VAD 静音切分（实测报告中列为"剩余空间"，待后续迭代评估）。
- 多 GPU / 集群化部署（本期单机单卡）。

### 2.4 设计原则：实现简单优先

以下取舍贯穿全文，评审时若与其他条款冲突，以本节为准：

1. **单一模型**：仅 int8-1.7B 常驻，无模型切换逻辑。
2. **单一提取路径**：浏览器端只做 ffmpeg.wasm 解封装（stream copy），统一封装为 MKA 容器，一条命令覆盖所有编码；不实现解码路径。
3. **无数据库**：任务状态即文件系统（任务目录 + 产物文件 + 一个状态 JSON），队列为进程内内存队列，不引入数据库/Redis/消息中间件。
4. **进度从简**：P0 只要求阶段级状态 + 按实时率估算的剩余时间，分块级百分比为 P1。
5. **轮询优先**：状态查询用 HTTP 轮询，不做 SSE/WebSocket。

## 3. 用户与使用场景

### 3.1 目标用户

| 用户 | 特征 | 诉求 |
|---|---|---|
| 内容创作者 / UP 主 | 有中文口播视频 | 快速拿到可直接使用的 SRT |
| 学习者 / 研究者 | 有课程、讲座录像 | 拿到带时间戳的文字稿便于检索 |
| 内网团队成员 | 会议、培训录像，内容敏感 | 视频不出本机、音频只进内网服务 |

### 3.2 核心用户故事

1. 作为用户，我在浏览器打开系统页面，选择一个本地 MKV/MP4 视频，页面显示"正在提取音频"，随后自动上传音频并开始转写；我能看到排队位置和转写进度；完成后我下载得到一个 SRT 文件，导入播放器即可使用。
2. 作为用户，如果我中途关闭页面，重新打开后凭任务链接/任务 ID、或直接从首页的「历史任务」列表点选，仍能取回结果；结果长期保留，只有我主动删除才会消失。

### 3.3 主流程（Happy Path）

```
选择视频 → 浏览器无损提取原始音轨(解封装,不重编码) → 上传音轨 → 创建任务入队
→ [服务端] ffmpeg 转 16kHz 单声道 WAV → ASR 转写 + 对齐 → 标点断句 → 排版规范化
→ 生成 SRT/TXT → 页面提示完成 → 预览 → 下载
```

## 4. 功能需求

需求优先级：P0 = 本期必须；P1 = 本期应有；P2 = 可延后。

### 4.1 前端（浏览器）

#### FR-F1 视频文件选择（P0）
- 支持通过文件选择框和拖拽两种方式选择本地视频文件。
- 支持常见容器格式：MP4、MKV、WebM、MOV、AVI、FLV、TS；以及纯音频文件：WAV、MP3、M4A、AAC、FLAC、OGG（纯音频文件跳过提取步骤，原文件直接上传）。
- 单文件处理；文件大小不设上限（视频不上传，仅本地读取）。
- 选择后展示文件名、大小、时长（可解析时）。

#### FR-F2 浏览器端音轨无损提取（P0）
- 在浏览器内对视频**只做解封装（demux / stream copy）**，原样取出音频码流，**不解码、不重采样、不重编码**——上传的音轨与视频内封装的音轨比特级一致（等价于 `ffmpeg -i in.mkv -vn -c:a copy`）。**视频画面数据不上传、不发送到任何服务器**。
- 提取产物**统一封装为 MKA（Matroska Audio）容器**——Matroska 可容纳任意编码的音频码流（AAC/MP3/Opus/AC3/DTS/FLAC/PCM 等），前端只需一条固定命令（`-vn -c:a copy out.mka`）、一条代码路径覆盖全部情况；封装容器改变但**音频码流本身不得改变**。
- 技术路线：ffmpeg.wasm 解封装（stream copy，纯复制不涉及编解码器，兼容性好、速度快）。**不实现浏览器解码路径**（含兜底），见 §2.4 设计原则。
- 提取过程显示进度；失败（无音轨、文件损坏、封装不支持）给出明确错误提示，并附自助方案（提示用户可用 `ffmpeg -i 视频 -vn -c:a copy 音频.mka` 自行抽取后作为纯音频文件上传）。
- 多音轨视频默认取第一条音轨（P2：允许用户选择音轨）。

#### FR-F3 音轨上传（P0）
- 直接上传 FR-F2 的无损提取产物，**不做任何有损压缩**。体积即原音轨大小，参考：10 分钟 AAC 128 kbps ≈ 10 MB、AC3 192 kbps ≈ 14 MB、FLAC/PCM 更大（受 FR-B1 大小上限约束，超限时提示用户）。
- 上传显示进度条，支持取消。
- 上传失败自动重试（≥1 次），仍失败则提示用户手动重试，无需重新提取音轨（提取产物在页面存活期内保留在内存中即可，不要求持久化）。

#### FR-F4 耗时预估展示（P0）
- 本期单一模式（int8-1.7B，见 §2.4），**无模式选择 UI**。
- 页面按音频时长 × RTF（≈ 0.65，服务端配置下发）展示预计处理时长（如"10 分钟视频约 6–7 分钟"）。
- P2：快速模式（0.6B）选择项。

#### FR-F5 进度与状态展示（P0）
- 任务状态至少包括：`排队中(含队列位置)` → `转写中` → `生成字幕中` → `已完成` / `失败(含原因)`。
- 转写中显示按 RTF 估算的预计剩余时间（前端即可计算，无需服务端细粒度进度）；P1：服务端分块级百分比（见 FR-B4）。
- 页面关闭后重开，可凭任务 ID（URL 参数）恢复状态查询（P0）；任务 ID 同时在页面上明示，便于用户保存。无 URL 参数时可从首页「历史任务」列表找回（见 FR-F8）。

#### FR-F6 结果预览与下载（P0）
- 完成后页面内预览字幕文本（按 cue 列表展示时间轴 + 文本）。
- 提供下载：`SRT`（默认，经标点断句 + 排版规范化）、`TXT`（带标点全文）。P1：`VTT`；P1：原始字级 SRT（未后处理版本，供高级用户）。
- 下载文件名默认沿用原视频文件名（如 `讲座.mkv` → `讲座.srt`）。
- 提供「删除结果」按钮，二次确认后调用删除接口（对应 FR-B7 的用户主动删除）。
- P2：页面内加载本地视频与生成字幕联动预览播放。

#### FR-F7 错误与边界提示（P0）
- 需覆盖并给出可理解提示的场景：无音轨、音频时长为 0、时长超上限（见 NFR-2）、服务不可用、队列已满、任务失败、结果已被用户删除。

#### FR-F8 历史任务列表（P1）
- 首页（空闲态）展示「历史任务」列表，来源为服务端已保留的任务，**最新在前**；每条显示：原文件名、状态（排队/处理中/已完成/失败/取消）、创建时间、音频时长（排队中附队列位置）。
- 点击任一条目即恢复该任务（等价于打开其 `?task=<id>` URL）：已完成 → 进入预览/下载；进行中 → 继续轮询进度；失败/取消 → 显示对应终态。
- 每条提供删除入口（复用 FR-B7 的删除接口，与 FR-F6「删除结果」同义），删除后从列表消失（已删除任务的墓碑不在列表中展示）。
- 提供手动刷新。列表数据来自服务端（非浏览器本地存储），因此**清缓存、换浏览器、换设备**均可找回——契合"文件系统即状态"（见设计 D3/D8）。
- 定位：本期单用户/内网，列表不做用户归属隔离（多用户隔离为范围外，见 §2.3）。

### 4.2 后端（服务）

#### FR-B1 音频接收接口（P0）
- 接收前端上传的原始音轨文件，编码/封装需覆盖视频常见音轨：AAC/M4A、MP3、Opus/Vorbis（OGG/WebM）、AC3/EAC3、DTS、FLAC、PCM/WAV、MKA 封装等——以 ffmpeg 能解码为准，不限定白名单编码。校验：
  - 文件类型（按内容嗅探，不信任扩展名/Content-Type）；
  - 时长上限与文件大小上限（默认：时长 ≤ 3 小时、大小 ≤ 200 MB，可配置）；
  - 解码可行性（ffmpeg 探测失败即拒绝）。
- 接收后统一用 ffmpeg 转为 16 kHz 单声道 PCM WAV 作为模型输入（模型输入要求所致；全链路唯一一次重采样发生在服务端，浏览器侧全程无损，见 FR-F2）。
- 返回任务 ID。

#### FR-B2 任务队列与调度（P0）
- **单 GPU 串行执行**：同一时刻至多一个 ASR 任务占用 GPU（4 GB 显存放不下并发，实测峰值 3.02 GB）。
- FIFO 队列，队列长度可配置（默认 10），满则拒绝新任务并返回明确错误。
- 每个任务有独立工作目录，记录状态机：`queued → preprocessing → transcribing → postprocessing → done / failed / cancelled / deleted`。
- **状态存储即文件系统**：任务目录内一个状态 JSON + 产物文件即全部持久化，队列为进程内内存队列，不引入数据库/Redis/消息中间件（见 §2.4）。
- 支持用户取消排队中的任务（P1：支持取消运行中任务）。
- 任务超时保护：单任务运行时长超过上限（默认 `音频时长 × 3 + 10 分钟`）强制终止并标记失败。

#### FR-B3 ASR 转写与对齐（P0）
- 复用已验证管线（`qwen3_asr_compare.py` 同等逻辑，重构为服务内模块）：
  - 模型：`Qwen3-ASR-1.7B` + `load_in_8bit`，`device_map={"": 0}`，全 GPU（本期唯一模型，见 §2.4）；
  - 对齐器 `Qwen3-ForcedAligner-0.6B` 固定在 CPU；
  - 分块 30 s（4GB 卡单块峰值留余量的默认；见实现与踩坑 §4.8）；
  - 语言自动识别（`language=None`）。
- 单任务内采用容量为 1 的两级流水线：GPU 执行第 `i+1` 块 ASR 时，CPU 对齐第 `i` 块；任务之间仍按 FR-B2 严格串行。不得把对齐器搬上 GPU，也不得无界积压待对齐块。
- 模型**常驻显存**（服务启动时加载一次，避免每任务 14 s 加载开销），服务生命周期内不卸载、不切换。
- 产物：带标点全文 + 逐 token 时间戳（即 `items.json` 结构），作为后处理输入并随任务保留。

#### FR-B4 进度上报（P0）
- P0：对外提供任务状态查询接口（HTTP 轮询），返回阶段级状态 + 队列位置 + 音频总时长（前端据此按 RTF 估算剩余时间）。
- P1：以 `N` 次 ASR + 至多 `N` 次对齐为真实工作单位，每完成一步更新百分比；两阶段因流水线而交错推进，静音块不执行对齐，故可在略低于 99% 时直接进入生成字幕阶段。
- 不做 SSE/WebSocket（见 §2.4）。

#### FR-B5 字幕后处理（P0）
- 依次执行已验证的两级后处理（复用 `build_srt_punct.py`、`build_srt_layout.py` 逻辑）：
  1. **标点断句**：把带标点全文对齐到 token 时间戳，按句读断句，还原英文空格；
  2. **排版规范化**：最短 1.0 s / 最长 7 s 显示时长、阅读速度 ≤ 9 字/秒（只借后向空隙、不移轴）、每行 ≤ 18 字两行折行、合并过短碎片、拉丁 token 与 jieba 中文词不劈开、消重叠。参数服务端可配置。
- 排版默认参数按中文标定；纯英文视频复用同一管线（拉丁 token 保护天然保证按单词折行），CPS/行宽等参数对英文的适配在 M3 用英文样本校验（见风险 R5）。
- 后处理纯 CPU，不占 GPU，可与下一个任务的 GPU 转写并行。

#### FR-B6 字幕文件生成与下发（P0）
- 生成 SRT（后处理版）与 TXT（带标点全文）；P1：VTT、原始字级 SRT。
- 提供按任务 ID 下载的接口；下载不限次数（用户删除前始终有效）。
- 提供任务列表接口（P1，支撑 FR-F8）：扫描任务目录返回各任务摘要，最新在前，默认不含已删除墓碑。

#### FR-B7 数据生命周期与清理（P0）
- 上传音频（原始 + 转码 WAV）在转写完成后**立即删除**。
- 字幕产物与 `items.json` **长期保留、不自动过期**：只有用户主动删除（删除接口 / 页面删除按钮）才清理，删除后立即从磁盘移除、不可再访问，任务状态转 `deleted`。
- 服务重启后：队列中未开始的任务丢失（返回错误提示用户重传）；已完成任务的产物不受影响，仍可下载（状态与产物落盘）。
- 除字幕产物、`items.json` 与任务运行日志（均不含音频内容）外，不留存任何用户数据。
- P1：管理侧提供磁盘占用统计（产物为 KB 级文本，正常使用下增长缓慢，暂不设配额）。

#### FR-B8 服务配置化（P1）
- 以下项通过配置文件/环境变量调整，不改代码：模型路径（支持本地目录，适配 ModelScope 预下载）、分块秒数、队列长度、时长/大小上限、产物存储目录、排版参数（min-dur/max-dur/cps/line-width）、监听地址与端口。

### 4.3 接口草案（指导实现，字段可在设计阶段细化）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/tasks` | POST | multipart 上传音频 + 参数（原文件名）；返回 `{task_id}`（P2 预留 mode 字段） |
| `/api/tasks` | GET | 历史任务列表（P1，FR-F8）：各任务摘要，最新在前 |
| `/api/tasks/{id}` | GET | 状态、队列位置、进度百分比、失败原因 |
| `/api/tasks/{id}` | DELETE | 排队中任务：取消；已完成任务：删除产物（用户主动删除的唯一途径） |
| `/api/tasks/{id}/result?format=srt\|txt\|vtt` | GET | 下载字幕产物 |
| `/api/health` | GET | 服务/GPU 健康状态（P1） |

## 5. 非功能需求

### NFR-1 性能（基于实测数据，单位为 10 分钟中文音频）
- 端到端（入队执行起算）：≤ 8 分钟（int8-1.7B 实测 6.4 分钟 + 余量）。
- 后处理（断句 + 排版）：≤ 5 秒。
- 实时率（RTF）参考 ≈ 0.65；页面预估耗时按此计算（服务端配置下发）。

### NFR-2 容量与限制
- 单任务音频时长上限：3 小时（默认，可配置）。按 RTF 0.65 折算约需 2 小时处理，需与任务超时上限联动。
- 队列长度：10（默认，可配置）。
- 并发下载/状态查询：≥ 20 并发连接（轻量接口，不受 GPU 约束）。

### NFR-3 资源约束（部署基线）
- 基线硬件即当前实测环境：4 GB 显存 NVIDIA GPU（Ampere，compute cap ≥ 8.6）、WSL2/Linux、内存 ≥ 16 GB。
- 显存预算：int8-1.7B 峰值 3.02 GB + CUDA 上下文 ~0.5 GB，**禁止**在 GPU 上叠加其他负载；对齐器固定 CPU。
- 更大显存环境的扩展路线（vLLM 服务化、并发）见实测报告附录 D/E，不在本期范围。

### NFR-4 兼容性
- 浏览器：最新两个大版本的 Chrome/Edge（P0），Firefox/Safari（P1）。解封装走 ffmpeg.wasm，不依赖浏览器编解码能力，各浏览器行为一致；仅需 WebAssembly 支持。
- 服务端：Linux（含 WSL2），Python 3.11，依赖清单以实测环境为准（torch 2.9.x、transformers 4.57.x、qwen-asr 0.0.6、bitsandbytes、jieba、ffmpeg 8.x）。

### NFR-5 安全与隐私
- 视频内容永不离开用户本机；服务端仅接触音频且用后即删（FR-B7）。字幕产物长期保留在服务端（部署方即数据保管方），用户可随时主动删除。
- 上传内容校验（FR-B1），任务 ID 使用不可猜测的随机串（≥ 128 bit），防止越权取他人结果。
- 本期定位内网/个人部署，不做账号鉴权；若公网暴露，须在反向代理层加访问控制（部署文档说明即可）。
- 服务进程以非特权用户运行；临时文件目录隔离。

### NFR-6 可观测性（P1）
- 任务级日志：各阶段耗时、显存峰值、音频时长、成败原因。
- `/api/health` 暴露 GPU 可用性、队列深度、当前任务。

## 6. 验收标准

1. **主流程**：用 `Transformer其实是个简单的架构.mkv`（606 s）走完整浏览器流程，仅上传音频（抓包验证无视频数据外发），产出 SRT；与离线管线产物 `*.1.7b-int8.layout.srt` 内容一致性 ≥ 99%（同模型同参数）。
2. **无损提取**：浏览器上传的音轨码流与 `ffmpeg -i 原视频 -vn -c:a copy` 抽取的码流**比特级一致**（对码流做 hash 比对，封装容器差异不计）。
3. **性能**：上述视频端到端 ≤ 8 分钟（不含上传与排队）。
4. **字幕质量门槛**（沿用排版层已验证指标）：无 < 1 s 或 > 7 s 的 cue；无 > 9.5 字/秒的 cue；拉丁 token（如 `w_k`、`QKV`）与 jieba 中文词无劈开。
5. **排队**：连续提交 3 个任务，串行执行、队列位置正确、互不干扰；第 11 个任务（队满）被明确拒绝。
6. **边界**：无音轨视频、超时长音频、损坏文件、服务重启、访问已删除结果各场景均有明确用户提示，服务不崩溃。
7. **清理与保留**：任务完成后服务端无残留音频文件；产物在用户主动删除前始终可下载（含服务重启后）；用户删除后磁盘上立即清除且接口返回明确的"已删除"提示。
8. **语言覆盖**：分别用纯英文和中英混合样本走通主流程，语言自动识别正确，产出字幕可用（英文按单词折行、无单词内断行）。

## 8. 风险与开放问题

| # | 风险/问题 | 影响 | 应对 |
|---|---|---|---|
| R1 | 个别封装/码流 ffmpeg.wasm 解封装（stream copy）异常 | 提取失败 | 明确报错并附自助方案（提示用户本地 `ffmpeg -c:a copy` 抽取后作为纯音频上传）；不实现浏览器解码兜底（§2.4） |
| R2 | 长音频（小时级）时间戳漂移、对齐空洞 | 个别 cue 时长异常 | 排版层 max-dur 封顶已兜底；日志打印被截断条目；后续迭代评估 VAD |
| R3 | 无损直传体积随原音轨码率走（FLAC/PCM/高码率 DTS 可达数百 MB） | 上传慢、触发大小上限 | 大小上限可配置；超限时前端提前计算并提示；长音频场景建议内网部署 |
| R4 | WSL2 环境下服务长稳性（显存碎片、驱动） | 偶发失败 | 任务级异常捕获 + 进程内 OOM 自愈（清缓存重试一次）；health 检查 |
| R5 | 排版参数按中文标定，纯英文视频的 CPS/行宽适配未实测 | 英文字幕观感欠佳 | M3 用英文样本校验；必要时按识别语言切换参数组（英文按字符 CPS ≈ 17、行宽 ≈ 42 字符起步调参） |

> 原开放问题已裁定并纳入正文：**Q1** 语言范围 = 纯中文、纯英文、中英混合（§2.2、验收 7）；**Q2** 结果不自动过期，仅用户主动删除（FR-B7、验收 6）。
